Running in CI/CD

Running nightly/regression builds

1️⃣ What is Zephyr? (Plain English)

Zephyr is a test management tool inside Jira.

If Jira is where you:

Track stories

Track bugs

Track tasks

👉 Zephyr is where you track testing:

Test cases

Test cycles

Test executions

Pass / Fail results

Test coverage

Think of it like this:

Jira = “What are we building?”
Zephyr = “Did we test it? What passed? What failed?”

2️⃣ Why teams use Zephyr

Without Zephyr:

Test cases live in Excel or Confluence

No direct link between:

Story → Test → Execution → Defect

Manual tracking = painful

With Zephyr:

Every test is tied to Jira issues

Every execution is recorded

Managers can see:

Coverage

Trends

Quality status

3️⃣ Core Zephyr Concepts (Very Important)

Let’s define the building blocks.

🧩 1. Test Case

A test case is:

A Jira issue (special type)

Represents one thing to test

Example:

Test Case: Verify user can log in with valid credentials


It has:

Steps

Expected result

Status (not executed, pass, fail)

🗂 2. Test Cycle

A test cycle is:

A collection of test cases executed together

Examples:

Nightly Run

Regression Cycle

Smoke Test Cycle

Example:

Cycle Name: Automation Chrome QA 2026-02-03

▶️ 3. Test Execution

A test execution is:

One test case run inside one test cycle

This is where:

Pass / Fail is recorded

Execution time is stored

Defects are linked

🐞 4. Defects

Defects (bugs) are normal Jira issues linked to:

Failed test executions

4️⃣ Zephyr + Automation (How it works)

This is the part that usually confuses beginners — so let’s go step by step.

🔁 High-Level Flow
Automation Test
   ↓
Framework (Java + Cucumber + TestNG)
   ↓
Zephyr API
   ↓
Jira / Zephyr

🧪 Step-by-Step Example
Step 1: You write an automation test

Example Cucumber scenario:

Scenario: Verify valid login
  Given user is on login page
  When user logs in with valid credentials
  Then dashboard is displayed

Step 2: Scenario is mapped to Zephyr test case

This mapping happens via:

Scenario tag (@RSA-T123)

OR scenario name

OR auto-creation logic

Example:

@RSA-T123
Scenario: Verify valid login


➡ RSA-T123 is a Zephyr Test Case in Jira

Step 3: Framework connects to Zephyr

Your framework:

Reads zapi.properties

Authenticates to Jira

Prepares test cycle

Step 4: Test cycle is created (if needed)

Based on config:

zephyr.test.type=Nightly
zephyr.cycle.name.nightly.pattern=Automation Chrome QA 2026-02-03


Zephyr creates:

Automated Test Cycles
 └── UI
     └── Automation Chrome QA 2026-02-03

Step 5: Automation runs tests

For each scenario:

Framework knows which Zephyr test it belongs to

Executes the test

Captures result (PASS / FAIL)

Step 6: Results are pushed to Zephyr

Framework calls Zephyr APIs to:

Create test execution

Update execution status

Attach logs/screenshots

Link defects (optional)

Step 7: Jira dashboard updates

Now stakeholders can see:

% passed

Failed tests

Linked bugs

Trends over time
